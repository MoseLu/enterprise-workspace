# 文档目录说明

本文档描述 `docs/` 目录下的文档组织结构，采用英文子目录命名规范，便于国际化协作和工具链集成。

## 目录结构

```
docs/
├── architecture/          # 架构设计文档
├── cicd/                  # CI/CD配置与规范
├── development/           # 开发规范与指南
└── middleware/            # 中间件配置与使用
```

## 子目录详解

### architecture/ — 架构设计文档

**用途**：存放系统整体架构、技术选型、设计决策等架构相关文档。

**包含内容**：

| 文档 | 说明 |
|------|------|
| `项目结构.txt` | 工作区标准目录结构规范，定义各层级的目录命名和文件组织方式 |
| `git仓库架构.txt` | Git仓库架构设计说明，包括子模块组织和版本管理策略 |

**适用场景**：

- 新成员了解系统整体架构
- 技术方案评审和设计决策记录
- 项目结构变更的参考标准

**相关文档**：

- [项目结构.txt](./architecture/项目结构.txt)
- [git仓库架构.txt](./architecture/git仓库架构.txt)

## 规范遵循

### 文档命名规范

1. **文件名使用英文或中文**：根据内容和使用场景选择
2. **扩展名明确**：
   - `.md`：Markdown格式文档
   - `.txt`：纯文本说明或配置
   - `.yml`/`.yaml`：YAML格式配置
   - `.json`：JSON格式配置
3. **避免空格**：使用连字符（`-`）或下划线（`_`）分隔单词

### 文档更新规范

1. **修改前备份**：重要文档修改前建议创建备份
2. **更新索引**：添加新文档后更新本文档索引
3. **版本控制**：重大变更记录到版本历史
