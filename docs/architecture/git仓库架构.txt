# 企业工作空间 Git 仓库架构

> 本文档描述企业工作空间的 Git 仓库架构设计，采用「顶层根仓库 + Git Submodule」模式，实现全局工程化整合与子仓库独立迭代的平衡。

## 一、核心设计原则

1. **顶层根仓库 = 全局工程化整合基座**：仅存放跨所有模块的全局配置、脚本、CI/CD 模板、文档，不包含业务核心代码，是整个项目的唯一入口；
2. **产品子仓库 = 高内聚独立业务模块**：产品模块采用 Git Submodule 管理，可独立启动、独立迭代、独立发布；
3. **参考项目 = 本地目录**：设计系统参考、移动端参考等项目作为本地目录，不纳入 Git 版本控制；
4. **版本隔离 + 全局锁定**：子仓库采用语义化版本独立打 Tag，顶层根仓库通过 Git Submodule 仅锁定产品子仓库的稳定版本。

## 七、团队协作规范

### 分支策略

- **main**：生产分支
- **develop**：开发分支
- **feature/**：功能分支
- **bugfix/**：修复分支
- **hotfix/**：紧急修复分支

### 提交规范

遵循 Conventional Commits：

```
<type>(<scope>): <description>

# 示例：
feat(agent-orchestrator): 添加 Agent 调度功能
fix(pc-admin): 修复用户列表分页问题
docs: 更新 API 文档
chore: 移除参考项目 submodule 配置
```

### 子仓库操作流程

#### 子仓库独立开发

```bash
# 进入子仓库目录
cd products/agent-orchestrator

# 创建开发分支
git checkout -b feature/new-feature

# 开发并提交
git add .
git commit -m "feat: 添加新功能"

# 推送到远程
git push origin feature/new-feature
```

#### 更新顶层根仓库

```bash
cd enterprise-workspace

# 更新子仓库到指定版本
cd products/agent-orchestrator
git checkout v1.0.0

# 回到顶层根仓库，提交变更
cd ../..
git add products/agent-orchestrator
git commit -m "chore: 更新 agent-orchestrator 到 v1.0.0"
git push origin develop
```

## 十、常见问题

### Q1：如何更新产品子仓库？

```bash
# 更新所有子仓库
git submodule update --init --recursive

# 或更新特定子仓库
git submodule update --init products/agent-orchestrator
```

### Q2：如何为子仓库添加远程分支？

```bash
cd products/agent-orchestrator
git remote add origin https://github.com/BellisGit/agent-orchestrator-platform.git
git fetch origin
git checkout -b main origin/main
git push -u origin main
```

### Q3：如何更新子仓库到新版本？

```bash
cd products/agent-orchestrator
git fetch origin
git checkout v1.1.0

# 回到顶层根仓库
cd ../..
git add products/agent-orchestrator
git commit -m "chore: 更新 agent-orchestrator 到 v1.1.0"
```

### Q4：参考项目如何同步最新代码？

参考项目不通过 Git Submodule 管理，如需同步最新代码：

```bash
# art-design-pro
cd references/art-design-pro
git fetch origin
git reset --hard origin/develop

# mobile-apps
cd references/mobile-apps
git fetch origin
git reset --hard origin/develop
```
