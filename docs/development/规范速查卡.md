# Enterprise Workspace 规范速查卡

> **规范等级**：强制执行（Mandatory）
>
> **适用范围**：所有子项目

## 一、分支命名（5 秒速查）

| 类型 | 命名 | 来源 | 目标 |
|------|------|------|------|
| 主分支 | `main` | - | 受保护 |
| 开发分支 | `develop` | - | 受保护 |
| 功能分支 | `feature/<名称>` | develop | develop |
| 修复分支 | `bugfix/<描述>` | develop | develop |
| 热修复 | `hotfix/<版本>` | main | main + develop |

**示例**：
```bash
# 创建功能分支
git checkout develop
git checkout -b feature/user-auth

# 创建热修复分支
git checkout main
git checkout -b hotfix/v1.2.1
```

## 二、提交消息格式（3 秒速查）

```
<type>(<scope>): <subject>

类型：feat | fix | docs | style | refactor | perf | test | chore | hotfix
```

**示例**：
```bash
feat(auth): add OAuth2 login support
fix(api): resolve timeout issue
hotfix: security patch for auth bypass
```

## 三、分支保护（2 秒速查）

| 分支 | 直接推送 | PR 合并 | CI 检查 | 审批 |
|------|---------|---------|---------|------|
| main | ❌ | ✅ 必须 | ✅ 必须 | 1 人 |
| develop | ❌ | ✅ 必须 | ✅ 必须 | 1 人 |

## 四、CI/CD 检查清单

每次 PR 必须通过：

- [ ] 分支命名正确
- [ ] 提交消息格式正确
- [ ] Lint 通过
- [ ] 测试通过
- [ ] 至少 1 人审批

## 五、工作流程

```
┌─────────────────────────────────────────────────────────┐
│                    标准开发流程                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 从 develop 创建分支                                  │
│     git checkout -b feature/xxx                         │
│                                                         │
│  2. 开发并提交                                          │
│     git commit -m "feat(scope): message"                │
│                                                         │
│  3. 推送到远程                                          │
│     git push -u origin feature/xxx                      │
│                                                         │
│  4. 创建 PR → develop                                   │
│     - 通过 CI 检查                                       │
│     - 获得 1 人审批                                      │
│     - 合并到 develop                                    │
│                                                         │
│  5. 从 develop 到 main（发布）                           │
│     - 创建 PR: develop → main                           │
│     - 通过所有检查                                       │
│     - 获得审批                                          │
│     - 合并到 main                                       │
│     - 创建标签: git tag -a v1.0.0                       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 六、紧急修复流程

```
┌─────────────────────────────────────────────────────────┐
│                    热修复流程                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 从 main 创建分支                                     │
│     git checkout -b hotfix/v1.2.1                       │
│                                                         │
│  2. 紧急修复                                            │
│     git commit -m "hotfix: critical fix"                │
│                                                         │
│  3. 合并到 main（立即发布）                              │
│     - 创建 PR: hotfix → main                            │
│     - 通过检查后合并                                     │
│     - 创建标签                                          │
│                                                         │
│  4. 同步到 develop                                       │
│     - 创建 PR: hotfix → develop                         │
│     - 合并                                              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 七、常见问题

### Q1: 分支命名可以用中文吗？

**❌ 不可以**。只能使用英文字母、数字、连字符、下划线。

### Q2: 忘记创建 PR 直接推送了？

**方案**：删除远程分支，重新按规范推送

```bash
# 删除远程分支
git push origin --delete feature/xxx

# 重新按规范操作
```

### Q3: CI 失败了怎么办？

1. 查看 GitHub Actions 日志
2. 修复问题
3. 重新提交

### Q4: 提交消息格式错了？

**修改提交消息**：

```bash
git commit --amend -m "feat(scope): correct message"
git push --force-with-lease
```

### Q5: 审批人不够？

联系团队成员请求审批。
